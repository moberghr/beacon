# Beacon web app

React 18, TypeScript, Vite and Tailwind CSS 3.4. This is the whole Beacon UI.

The source lives here (`src/Beacon.UI/web`). It builds into `src/Beacon.UI/wwwroot/beacon` and ships in the
`Beacon.UI` Razor Class Library (NuGet `Moberg.Beacon.UI`), which serves it under **`/beacon`**. `BrowserRouter`
uses `basename="/beacon"` and Vite builds with `base: '/beacon/'`, so in-app links are written without the prefix:
`/projects`, not `/beacon/projects`.

## Requirements

- Node 22 and npm 11. `package-lock.json` was generated by npm 11 and only validates under it; CI pins npm
  11.11.0.
- The .NET 10 SDK, for the backend and for codegen.

Run the npm commands below from `src/Beacon.UI/web`. Run the `dotnet` commands from the repository root.

## Dev loop

```bash
# Terminal 1, repository root: the sample host on https://localhost:7187
dotnet run --project src/Beacon.SampleProject --launch-profile https

# Terminal 2, src/Beacon.UI/web
npm install
npm run dev
# → http://localhost:5173/beacon/
```

Vite proxies `/beacon/api` (including the SignalR hub at `/beacon/api/hub`) and `/beacon/mcp` to
`https://localhost:7187`. Set `BEACON_BACKEND_URL` to point it elsewhere. Cookies pass through the proxy, so
signing in through http://localhost:5173/beacon/ authenticates the app.

### Without a backend

```bash
npm run dev:mock
```

Runs the UI against in-browser MSW fixtures from `src/mocks/` (`VITE_MOCK_API=1`). The script sets the variable
inline, so it needs a POSIX shell. The documentation screenshots are taken in this mode.

## Production build

```bash
npm run build   # tsc -b && vite build → ../wwwroot/beacon
```

`dotnet build src/Beacon.UI -c Release`, or a Release build of anything that references it, runs `npm ci` (when
`node_modules` is missing) and `npm run build` for you. In Debug the React build is skipped unless you pass
`-p:BuildReactInDebug=true`.

## TypeScript codegen

The backend's OpenAPI document (`/openapi/v1.json`) is the contract. NSwag generates a typed fetch client from it.

```bash
# Repository root, once: restore the local nswag tool
dotnet tool restore

# With the backend running at https://localhost:7187, from src/Beacon.UI/web:
npm run codegen
```

Output goes to `src/api/generated/beacon-api.ts`. Do not edit it by hand.

## Tests

```bash
npm run test         # vitest run
npm run test:watch   # vitest in watch mode
```

Vitest, React Testing Library and MSW. Tests sit next to the code they test.

## Where things live

- `src/components/beacon/`: the Beacon design-system primitives (`Button`, `Card`, `Pill`, `KPI`, `Banner`,
  `Modal`, `Input`/`Field`, `Seg`, `Kbd`, `PageHeader`, `BeaconHero`). Use these instead of hand-rolled chrome.
- `src/index.css`: CSS variables under `:root` that the Tailwind config maps onto semantic names (`bg-brand-500`,
  `bg-surface`, `text-text-muted`, `bg-ok-bg`, …), plus the `@layer components` helpers. Dark theme via
  `document.documentElement.dataset.theme = 'dark'`.
- `src/routes/<area>/`: one folder per page area, with its `queries.ts` next to the components.
- `src/lib/api.ts`, `src/lib/csrf.ts`: the fetch wrapper (cookies and the antiforgery header).
- `src/auth/useAuth.ts`: the React Query hook for the current user (`/beacon/api/auth/me`).
- `src/api/generated/`: NSwag output.
- `src/mocks/`: MSW handlers for `dev:mock` and the tests.

Icons come from `lucide-react`.
